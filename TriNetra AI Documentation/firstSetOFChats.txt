That is the structure I recommend.

The key change is that Phase 1 is no longer one giant implementation task. It is a research pipeline with explicit checkpoints. The input format, including structured JSON evidence, is defined in Subphase 1.3, while the actual reconciliation engine comes later in Subphases 1.8 through 1.11.

Most importantly, Antigravity first learns the project documentation, then freezes the research specification, then builds the foundation, and every stage ends with a pass/fail validation. This avoids the current documentation problem where future performance figures such as 85% precision or 87% precision can accidentally become implementation targets before the experiment has produced them. The existing documentation currently contains such targets and claims, so Phase 1 should establish the actual results independently.

This is the version I would use as the master Phase 1 README.
