# PHASE 0 README

## Research Specification and Project Foundation

```text
# TriNetra AI
## Phase 0: Research Specification and Project Foundation

### Role

You are the Lead Systems Architect and Academic Research Engineer for TriNetra AI.

You are preparing the project for controlled implementation and research evaluation.

Do not write Phase 1 code yet.

---

## 1. Project Context

TriNetra AI investigates whether independently generated evidence from multiple e-commerce stakeholders can be normalized, connected through a common product identity, and reconciled to identify inconsistencies.

Potential stakeholders:

- Marketplace
- Seller
- Warehouse / Fulfillment Center
- Packaging operation
- Logistics provider
- Delivery system
- Return center

TriNetra is not an automatic fraud accusation system.

It detects observable inconsistencies and produces evidence-backed verification results.

---

## 2. Research Question

Define and freeze the primary research question:

"Can multi-source, cross-organizational evidence reconciliation reduce false negatives compared with single-source verification when identifying inconsistencies in e-commerce product lifecycles?"

Create supporting research questions covering:

- Entity resolution
- Evidence normalization
- Cross-source consistency
- Weight anomaly detection
- Temporal consistency
- Missing evidence
- Multi-source conflict detection
- Evidence completeness
- Human verification

---

## 3. Research Rules

Freeze these rules:

1. Never invent evidence.
2. Never infer guilt from an inconsistency alone.
3. Never label a stakeholder fraudulent without ground truth.
4. Preserve original evidence.
5. Normalize evidence without destroying provenance.
6. Separate deterministic validation from statistical anomaly detection.
7. Keep research experiments reproducible.
8. Do not manufacture target metrics.

---

## 4. Define the Evidence Model

Create an evidence taxonomy.

Required source types:

- ORDER
- SELLER
- MARKETPLACE
- WAREHOUSE
- PACKAGING
- CARRIER
- DELIVERY
- RETURN

Required evidence categories:

- Identity
- Attribute
- Physical measurement
- Temporal
- Status
- Image metadata
- Provenance
- Completeness

---

## 5. Define Conflict Taxonomy

Create formal definitions for:

- IDENTITY_CONFLICT
- SKU_CONFLICT
- VARIANT_CONFLICT
- WEIGHT_ANOMALY
- TEMPORAL_CONFLICT
- MISSING_EVIDENCE
- DUPLICATE_EVIDENCE
- MULTI_SOURCE_CONFLICT

For each conflict define:

- Meaning
- Required inputs
- Detection method
- Ground-truth representation
- Expected output

---

## 6. Define Research Baselines

Freeze:

Baseline 1:
Identity-only verification.

Baseline 2:
Weight-only anomaly detection.

Baseline 3:
Timeline-only verification.

TriNetra:
Multi-source reconciliation.

---

## 7. Define Evaluation Metrics

The minimum metrics are:

- Precision
- Recall
- F1 Score
- False Positive Rate
- False Negative Rate
- False Negative Reduction

Define the mathematical formula for each metric.

---

## 8. Define Phase 1 Scope

Phase 1 includes only:

- PostgreSQL
- Canonical normalization
- Entity resolution
- Synthetic data generation
- Deterministic reconciliation
- Statistical weight anomaly detection
- Baselines
- Evaluation

Phase 1 excludes:

- React
- REST APIs
- Redis
- Kafka
- Microservices
- LLM
- Customer portal
- Production deployment
- External integrations
- Authentication

---

## 9. Repository Structure

Create:

trinetra-ai/
├── docs/
├── phase-1/
├── phase-2/
├── backend/
├── frontend/
├── data/
├── experiments/
└── README.md

Inside docs create:

- RESEARCH_SPECIFICATION.md
- EVIDENCE_MODEL.md
- CONFLICT_TAXONOMY.md
- EVALUATION_PROTOCOL.md
- PHASE_ROADMAP.md

---

## 10. Required Output

Do not implement Phase 1.

Create the complete research specification and repository structure.

At completion provide:

1. Research specification
2. Evidence taxonomy
3. Conflict taxonomy
4. Baseline definitions
5. Evaluation definitions
6. Phase 1 scope
7. Repository structure

STOP.

Wait for explicit approval before starting Phase 1.
```

# PHASE 4 README

## Explainability Layer

```text
# TriNetra AI
## Phase 4: Explainability

### Objective

Create evidence-backed explanations.

---

## Core Rule

The explanation system must never invent evidence.

It can only describe:

- observed values
- detected conflicts
- executed checks
- actual evidence sources
- actual recommendations

---

## Pipeline

Evidence
→ Reconciliation
→ Structured findings
→ Explanation template
→ Optional LLM wording
→ Validation
→ Final explanation

---

## Structured Finding Example

Conflict:

Warehouse weight = 900g
Carrier weight = 905g
Return weight = 200g

Explanation:

"The outbound warehouse and carrier measurements are consistent, while the recorded return weight differs substantially."

Never introduce a fact that does not exist in the structured findings.

---

## LLM Requirements

If an LLM is used:

- send only structured findings
- constrain output
- validate generated statements
- reject unsupported claims
- preserve source citations
- keep deterministic underlying decisions

The LLM must explain the decision.

It must not make the decision.

---

## Testing

Test:

- factual consistency
- evidence citation
- hallucination resistance
- explanation clarity
- deterministic underlying verdict

STOP.
```
