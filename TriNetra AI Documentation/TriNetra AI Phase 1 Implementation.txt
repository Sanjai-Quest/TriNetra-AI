## Phase 1 Scope (FINAL - DON'T EXPAND)

### What You WILL Build

1. **PostgreSQL Schema**
   - `entity_resolution` (maps org-specific IDs to canonical product)
   - `evidence_record` (one row per evidence record)
   - `evidence_attribute` (normalize individual attributes)

2. **Python Normalization Engine**
   - SKU: "TS-204", "TS204", "ts204" → "TS-204"
   - Weight: "500g", "0.5kg", "500 grams" → 500 (in grams)
   - Size: "Extra Large", "XL", "extra large" → "XL"
   - Timestamp: Multiple formats → ISO 8601
   - Color: Variations → canonical form

3. **Entity Resolution**
   - Map Seller's "PROD-001" + Warehouse's "SKU-2845" + Carrier's "PKG-9999" → canonical "PRODUCT-UUID"
   - Track resolution confidence (deterministic confidence = 100%)

4. **Synthetic Data Generator**
   - Create 500-1000 product lifecycles with injected conflicts
   - Conflict types: Identity mismatch, SKU mismatch, weight anomaly, temporal ordering, missing evidence
   - Include ground truth labels (CONFLICT or NO_CONFLICT)

5. **Reconciliation Engine**
   - **Deterministic:** Check identity consistency, attribute matching, timeline ordering
   - **Statistical:** Weight anomaly detection (mean ± 3×stddev tolerance)
   - Produce structured output: conflicts detected, evidence sources, recommendation

6. **Three Baselines**
   - Baseline 1: Identity-only verification
   - Baseline 2: Weight-only anomaly detection
   - Baseline 3: Timeline-only verification
   - Compare each against TriNetra multi-source reconciliation

7. **Evaluation & Metrics**
   - Precision, Recall, F1
   - False Positive Rate (FPR)
   - False Negative Rate (FNR)
   - **Primary metric: False Negative Reduction** (TriNetra vs. baselines)
   - Confusion matrices per baseline

```
┌─────────────────────────────────────────────────────────┐
│                    PHASE 1 WORKFLOW                      │
└─────────────────────────────────────────────────────────┘

STEP 1: Generate Synthetic Data
   Input: TriNetra-defined lifecycle template
   Output: 1000 synthetic cases with ground truth
   
   Example case:
   {
     "order_id": "ORD-001",
     "product_id": "PROD-001",
     "evidence": [
       {"source": "SELLER", "sku": "TS-204", "weight": 500},
       {"source": "WAREHOUSE", "sku": "TS-204", "weight": 505},
       {"source": "CARRIER", "weight": 500},
       {"source": "RETURN", "weight": 210}  ← ANOMALY!
     ],
     "ground_truth": "CONFLICT"
   }

STEP 2: Store in PostgreSQL
   Tables:
   - entity_resolution (map IDs)
   - evidence_record (store evidence)
   - evidence_attribute (normalize attributes)

STEP 3: Run Baselines
   Baseline 1: Process SELLER + RETURN SKU only
   Baseline 2: Process weights only
   Baseline 3: Process timestamps only
   
   Output: Predictions for each baseline

STEP 4: Run TriNetra Multi-Source
   Process: Identity + Weight + Timeline + All sources
   
   Output: Predictions from full reconciliation

STEP 5: Evaluate
   Compare: Baseline predictions vs. TriNetra predictions vs. ground truth
   
   Metrics:
   - FN rate (baseline): X%
   - FN rate (TriNetra): Y%
   - FN Reduction: (X-Y)/X = Z%
   
   Result: If Z > 0 and statistically significant → ✅ HYPOTHESIS VALIDATED

STEP 6: Ablation Study
   Test component importance:
   - Identity only
   - Identity + Weight
   - Identity + Timeline
   - Identity + Weight + Timeline
   - Full reconciliation + all evidence sources
   
   Output: Confirm which evidence sources contribute to FN reduction
```

## Database Schema (Minimal)

```sql
-- Entity Resolution
CREATE TABLE entity_resolution (
  id SERIAL PRIMARY KEY,
  canonical_product_id UUID NOT NULL,
  source_organization VARCHAR(50) NOT NULL,
  source_system_id VARCHAR(100) NOT NULL,
  mapping_confidence FLOAT NOT NULL,
  created_at TIMESTAMP DEFAULT NOW()
);

-- Evidence Record
CREATE TABLE evidence_record (
  id SERIAL PRIMARY KEY,
  evidence_id UUID NOT NULL,
  canonical_product_id UUID NOT NULL,
  source_organization VARCHAR(50) NOT NULL,
  event_type VARCHAR(50) NOT NULL,
  timestamp TIMESTAMP NOT NULL,
  created_at TIMESTAMP DEFAULT NOW()
);

-- Evidence Attribute
CREATE TABLE evidence_attribute (
  id SERIAL PRIMARY KEY,
  evidence_id UUID NOT NULL,
  attribute_name VARCHAR(100) NOT NULL,
  original_value VARCHAR(255),
  normalized_value VARCHAR(255) NOT NULL,
  unit VARCHAR(50),
  data_type VARCHAR(50) NOT NULL,
  confidence FLOAT DEFAULT 1.0
);

-- Ground Truth (for evaluation)
CREATE TABLE ground_truth (
  case_id UUID PRIMARY KEY,
  expected_status VARCHAR(50),  -- 'CONSISTENT' or 'CONFLICT'
  conflict_type VARCHAR(100),
  severity VARCHAR(50)
);

-- Predictions
CREATE TABLE predictions (
  case_id UUID PRIMARY KEY,
  baseline_1_prediction VARCHAR(50),
  baseline_2_prediction VARCHAR(50),
  baseline_3_prediction VARCHAR(50),
  trinetra_prediction VARCHAR(50),
  trinetra_confidence FLOAT
);
```

## What Each Conflict Type Looks Like

### Conflict Type 1: IDENTITY_CONFLICT
```
Order:     Product ID = "PROD-001"
Seller:    Product ID = "PROD-002"  ← Different!
Warehouse: Product ID = "PROD-001"

Result: CONFLICT
Reason: Seller dispatched wrong product
Recommendation: Verification required before dispatch
```

### Conflict Type 2: SKU_CONFLICT
```
Order:     SKU = "TS-204"
Warehouse: SKU = "TS-203"  ← Wrong SKU!
Carrier:   Weight = 500g
Return:    SKU = "TS-204"

Result: CONFLICT
Reason: Warehouse packed wrong variant
Recommendation: Verification required
```

### Conflict Type 3: WEIGHT_ANOMALY
```
Outbound (Warehouse): 500g
Carrier pickup:       505g (±5g OK)
Delivery:             500g
Return:               210g  ← HUGE DROP!

Result: CONFLICT
Reason: Product missing from return (50% weight loss)
Recommendation: Verify customer didn't remove product
```

### Conflict Type 4: TEMPORAL_CONFLICT
```
Order timestamp:     2026-08-23 10:00:00
Warehouse timestamp: 2026-08-23 09:30:00  ← BEFORE order!
Carrier timestamp:   2026-08-23 12:00:00

Result: CONFLICT
Reason: Timeline ordering violated
Recommendation: Check data quality
```

### Conflict Type 5: MISSING_EVIDENCE
```
Order:     ✓ Present
Seller:    ✓ Present
Warehouse: ✓ Present
Carrier:   ✗ Missing
Return:    ✓ Present

Result: INCOMPLETE (not CONFLICT, but INCONCLUSIVE)
Reason: Can't fully reconcile without carrier evidence
Recommendation: Request carrier data
```

## Synthetic Data Generation Strategy

### Generate Normal Case (90% of data)
```
Product created
  → Seller dispatches (attributes match)
  → Warehouse receives (attributes still match)
  → Weight measured (505g, ±5g variance OK)
  → Carrier picks up (weight consistent)
  → Delivery confirmed
  → Customer keeps product
  
Result: NO_CONFLICT
```

### Inject IDENTITY_CONFLICT (3% of data)
```
Product created as TS-204 XL
  → Seller dispatches TS-203 L  ← WRONG!
  → Warehouse receives TS-203 L
  → Return with TS-203 L
  
Result: CONFLICT
Truth: Seller error (dispatched wrong variant)
```

### Inject WEIGHT_ANOMALY (4% of data)
```
Order: T-shirt (500g)
  → Outbound: 500g ✓
  → Carrier: 505g ✓ (acceptable variance)
  → Return: 210g ← PRODUCT MISSING!
  
Result: CONFLICT
Truth: Customer didn't return product in package
```

### Inject TEMPORAL_CONFLICT (2% of data)
```
Order placed: 2026-08-23 10:00
Seller dispatch: 2026-08-23 09:30  ← BEFORE order!

Result: CONFLICT
Truth: Data quality issue (likely timestamp error)
```

### Inject MISSING_EVIDENCE (1% of data)
```
Order: Complete
Seller: Complete
Warehouse: Complete
Carrier: ← MISSING DATA
Return: Complete

Result: INCONCLUSIVE
Truth: Can't assess without carrier evidence
```

## Python Implementation Strategy (High-Level)

```python
# Phase 1: Simple, reproducible, NOT optimized

class SyntheticDataGenerator:
    def generate_lifecycle(self):
        """Generate a single product lifecycle with optional conflicts"""
        order = create_order()
        evidence = [
            seller_dispatch(order),
            warehouse_receive(order),
            carrier_pickup(order),
            delivery(order),
            return_center(order)
        ]
        return apply_conflict(evidence, conflict_type)

class CanonicalNormalizer:
    def normalize(self, evidence):
        """Normalize evidence values to canonical form"""
        evidence['sku'] = normalize_sku(evidence['sku'])
        evidence['weight'] = normalize_weight(evidence['weight'])
        evidence['timestamp'] = normalize_timestamp(evidence['timestamp'])
        return evidence

class EntityResolver:
    def resolve(self, evidence_list):
        """Map org-specific IDs to canonical product ID"""
        canonical_id = extract_sku(evidence[0])  # Use first SKU as anchor
        for e in evidence:
            if e['sku'] != canonical_id:
                return None  # Conflict!
        return canonical_id

class ReconciliationEngine:
    def reconcile(self, normalized_evidence):
        """Check for conflicts across sources"""
        conflicts = []
        
        # Check identity consistency
        if not check_identity_consistent(normalized_evidence):
            conflicts.append('IDENTITY_CONFLICT')
        
        # Check weight anomaly
        if check_weight_anomaly(normalized_evidence):
            conflicts.append('WEIGHT_ANOMALY')
        
        # Check temporal ordering
        if not check_temporal_ordering(normalized_evidence):
            conflicts.append('TEMPORAL_CONFLICT')
        
        if conflicts:
            return {'status': 'CONFLICT', 'conflicts': conflicts}
        else:
            return {'status': 'CONSISTENT', 'conflicts': []}

class Baseline1IdentityOnly:
    def predict(self, evidence_list):
        """Single-source: Check if all sources agree on identity"""
        skus = [e.get('sku') for e in evidence_list]
        if len(set(skus)) == 1:
            return 'CONSISTENT'
        else:
            return 'CONFLICT'

class Baseline2WeightOnly:
    def predict(self, evidence_list):
        """Single-source: Check if weight is anomalous"""
        weights = [e.get('weight') for e in evidence_list if e.get('weight')]
        if check_weight_anomaly(weights):
            return 'CONFLICT'
        else:
            return 'CONSISTENT'

class Baseline3TimelineOnly:
    def predict(self, evidence_list):
        """Single-source: Check if timestamps are ordered correctly"""
        if check_temporal_ordering(evidence_list):
            return 'CONSISTENT'
        else:
            return 'CONFLICT'

# Evaluation
evaluator = Evaluator()
predictions = []

for case in test_cases:
    normalized = normalizer.normalize(case['evidence'])
    
    # Baseline predictions
    b1 = Baseline1IdentityOnly().predict(normalized)
    b2 = Baseline2WeightOnly().predict(normalized)
    b3 = Baseline3TimelineOnly().predict(normalized)
    
    # TriNetra prediction
    trinetra = ReconciliationEngine().reconcile(normalized)
    
    # Store prediction
    predictions.append({
        'case_id': case['id'],
        'ground_truth': case['ground_truth'],
        'baseline_1': b1,
        'baseline_2': b2,
        'baseline_3': b3,
        'trinetra': trinetra['status']
    })

# Evaluate
metrics = evaluator.evaluate(predictions)
print(f"FN Reduction: {metrics['fn_reduction']:.1%}")
print(f"Precision: {metrics['precision']:.2f}")
print(f"Recall: {metrics['recall']:.2f}")
```
